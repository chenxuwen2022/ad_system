# 提示词管理

## 分类与版本

分类用于发布边界，而不是给每条提示词单独维护一个“线上版本号”：

| 分类 | 提示词 |
| --- | --- |
| 商拍提示词 | 生产品报告、生商拍策划、生图提示词 |
| 微调提示词 | 产品报告微调、商拍策划微调、生图提示词微调 |
| 意图识别提示词 | 意图识别 |

每条提示词的编辑产生不可变的修订号。发布一个分类时，数据库在同一事务内创建该分类的完整快照，分类版本号递增。即使只改其中一条，快照仍记录全部成员的修订号。因此商拍三条一起修改时只需发布一次；历史版本能够准确还原当时三条提示词的组合。保存修订不改变线上工作流，只有发布后才生效。

## 数据表

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `prompt_template` | `key` 主键、`category`、`name`、`draft_revision_id` | 稳定的提示词身份和当前草稿指针 |
| `prompt_revision` | `id` 主键、`template_key`、`number`、`content`、`note`、`created_at`、`is_deleted` | 不可变内容历史；删除仅设置标记，`(template_key, number)` 唯一 |
| `prompt_release` | `id` 主键、`category`、`number`、`note`、`created_at` | 分类发布记录，`(category, number)` 唯一 |
| `prompt_release_item` | `(release_id, template_key)` 复合主键、`revision_id` | 发布快照里的每条提示词修订 |

首次访问管理接口时，系统从现有 `constant.py` 为七条提示词建立修订 #1 和各分类 v1。运行时按最新的分类发布记录读取内容；数据库暂时不可用时回退到代码内的初始提示词。部署时先执行 Alembic 迁移，再使用管理页。

## 页面与接口

页面 `/prompts` 提供分类切换、分类版本、提示词列表、编辑区、修订历史和发布历史。可从历史修订载入内容，并保存成新的草稿修订。

删除操作针对单条修订版本，后端禁止删除提示词的最后一个可用修订（HTTP 409），前端同时禁用该按钮。删除当前已发布的修订时，系统自动创建新的分类发布快照，并将该提示词指向剩余的最新修订；例如删除意图识别修订 #2 后立即使用修订 #1。删除标记不清除旧发布快照的审计记录。新增的自定义提示词进入管理和版本快照，但需要业务代码引用其 `key` 才会参与实际工作流。

- `GET /api/prompts`：分类及草稿、当前发布修订
- `POST /api/prompts`：新增提示词；同一标识的已归档项可重新启用
- `GET /api/prompts/{key}`：读取单条提示词详情
- `PUT /api/prompts/{key}`：修改名称或内容，产生新的不可变修订；使用 `expected_revision_id` 防止覆盖并发修改
- `DELETE /api/prompts/{key}`：删除当前草稿修订；最后一个可用修订不能删除
- `GET /api/prompts/{key}/revisions`：单条提示词修订历史
- `POST /api/prompts/{key}/revisions`：保存新草稿修订
- `DELETE /api/prompts/{key}/revisions/{revision_id}`：删除指定修订；删除当前发布修订时自动切换并发布
- `GET /api/prompts/categories/{category}/releases`：分类发布历史及其成员修订号
- `POST /api/prompts/categories/{category}/release`：发布分类完整快照
