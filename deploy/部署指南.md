# 数语深流 · 千川素材投放台 —— 服务器部署指南
> 适用：Linux（Ubuntu/Debian/CentOS）为主，Windows Server 备选方案见文末。
> 部署包位置：本项目 `deploy/` 目录（deploy.sh + nginx_ad_system.conf 已内置脚本中）。

## 一、部署架构

```
用户浏览器
    │  HTTPS(443) / HTTP(80)
    ▼
Nginx 反向代理  ──►  uvicorn(127.0.0.1:8000, 单进程)  ──►  FastAPI 应用
                             │
                             ├── SQLite 数据库 token_store.db（token + 账户列表）
                             ├── media_storage/（上传/临时素材）
                             └── /data/test素材（本地素材库，环境变量 LOCAL_MATERIAL_DIR 指定）
```

- **为什么单进程**：项目使用 SQLite（`check_same_thread=False`），多 worker 并发写会锁库。`deploy.sh` 的 systemd 服务已固定单进程。
- **8000 端口只监听 127.0.0.1**：不直接对外，统一走 Nginx，安全且便于后续加 HTTPS。

## 二、服务器要求

| 项 | 最低要求 | 建议 |
|---|---|---|
| 系统 | Ubuntu 20.04+ / Debian 11+ / CentOS 7+ | Ubuntu 22.04 LTS |
| CPU/内存 | 1核 / 1GB | 2核 / 2GB（千川报表拉取耗内存） |
| Python | 3.10+（代码使用新版语法） | 3.10–3.12 |
| 存储 | 10GB | 素材多的店铺按素材量扩容 |
| 带宽 | 5Mbps | 与素材上传/预览体量匹配 |

## 三、部署前要准备的信息

1. **服务器系统版本**（决定包管理命令，脚本已兼容 apt/yum）
2. **素材目录在服务器上的位置**（默认 `/data/test素材`，可改）
3. **是否有域名**（有→配 HTTPS；没有→先 IP+80 用，或 WITH_NGINX=0 直连 8000）

## 四、Linux 部署（推荐，一键脚本）

### 步骤 1：上传代码到服务器
在本机 PowerShell 执行（把代码打包传过去）：
```powershell
# 打包（排除 venv 等本地环境）
cd C:\Users\33082\PycharmProjects\ad_system
tar -czf ad_system.tar.gz --exclude=venv --exclude=__pycache__ --exclude=.git .
# 上传（换成你的服务器 IP 与用户名）
scp ad_system.tar.gz deploy\deploy.sh 用户名@服务器IP:/tmp/
```

### 步骤 2：服务器上执行
```bash
ssh 用户名@服务器IP
cd /tmp
sudo mkdir -p /opt/ad_system && sudo tar -xzf ad_system.tar.gz -C /opt/ad_system
sudo cp deploy.sh /opt/ad_system/deploy.sh   # 若已解压含 deploy.sh 可跳过
cd /opt/ad_system
sudo bash deploy.sh
```

### 步骤 3：迁移数据（关键）
> 本地已有的**授权状态**（2 个真实店铺 + 千川 token 缓存）都在 `token_store.db` 里，务必一并迁移，否则要在服务器上重新授权。

```bash
# 本机导出 token_store.db（PowerShell）
Copy-Item "C:\Users\33082\PycharmProjects\ad_system\token_store.db" .
scp token_store.db 用户名@服务器IP:/tmp/

# 服务器导入
sudo cp /tmp/token_store.db /opt/ad_system/token_store.db
sudo chown ad_system:ad_system /opt/ad_system/token_store.db
```

素材目录迁移（本机 C:\test素材 → 服务器 /data/test素材）：
```bash
# 服务器上建目录并放素材（或用 scp -r 整个目录传上去）
sudo mkdir -p /data/test素材
# 本机： scp -r "C:\test素材\*" 用户名@服务器IP:/data/test素材/
sudo chown -R ad_system:ad_system /data/test素材
```

### 步骤 4：验证
```bash
# 1) 服务状态
systemctl status ad_system
# 2) 页面
curl -s http://127.0.0.1:8000/ | head -c 200
# 3) 素材接口（应返回素材列表，而非"目录不存在"）
curl -s http://127.0.0.1:8000/api/local_materials
# 4) 账户接口（应返回迁移过来的两个店铺）
curl -s http://127.0.0.1:8000/api/advertisers
```
浏览器访问 `http://服务器IP/`（Nginx）或 `http://服务器IP:8000/`（直连）。

## 五、数据迁移清单（汇总）

| 数据 | 本地位置 | 服务器位置 | 说明 |
|---|---|---|---|
| SQLite 数据库 | `token_store.db` | `/opt/ad_system/token_store.db` | 含账户列表 + token 缓存，**必须迁移** |
| 本地素材库 | `C:\test素材` | `/data/test素材`（可改） | 代码通过环境变量 `LOCAL_MATERIAL_DIR` 读取 |
| 上传目录 | `media_storage/` | `/opt/ad_system/media_storage/` | 脚本已自动创建 |

## 六、Windows Server 部署（备选）

若服务器是 Windows Server：

1. 安装 Python 3.10+（勾选 Add to PATH），装 Git 可选
2. 代码放到 `C:\ad_system`
3. PowerShell 管理员：
```powershell
cd C:\ad_system
python -m venv venv
venv\Scripts\pip install -r requirements.txt
# 设置素材目录环境变量（持久化）
[Environment]::SetEnvironmentVariable("LOCAL_MATERIAL_DIR", "D:\test素材", "Machine")
# 前台启动测试
venv\Scripts\python main.py
```
4. 开机自启（两种任选）：
   - **任务计划程序**：新建任务 → 触发器"启动时" → 操作 `C:\ad_system\venv\Scripts\python.exe main.py`，工作目录 `C:\ad_system`
   - 或用 NSSM 注册为服务：`nssm install ad_system "C:\ad_system\venv\Scripts\python.exe" "main.py"`（工作目录设为 C:\ad_system）
5. 防火墙放行 8000（或按需），本地素材库路径用 `LOCAL_MATERIAL_DIR` 环境变量指定

## 七、安全与运维

- **敏感信息**：`config.py` 内含千川 App Secret 与 DeepSeek API Key。服务器上执行：
  ```bash
  sudo chmod 600 /opt/ad_system/config.py
  ```
  不要把项目推到公开仓库；如需备份，`token_store.db` 同样限制权限。
- **HTTPS（有域名时）**：Nginx 装好后：
  ```bash
  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d 你的域名
  ```
- **防火墙**：只放行 80/443（脚本已处理）；8000 仅本机监听，无需对外。
- **备份（建议每周）**：
  ```bash
  sudo cp /opt/ad_system/token_store.db /opt/ad_system/backups/token_store_$(date +%F).db
  ```
- **日常日志**：`journalctl -u ad_system -f`
- **代码更新**：重新上传代码后 `sudo systemctl restart ad_system`

## 八、常见坑（部署前必读）

| 坑 | 说明与处理 |
|---|---|
| `ModuleNotFoundError: sqlalchemy / multipart` | 本地 requirements.txt 曾缺失这两项，**已补**；用新 requirements.txt 安装即可 |
| 素材接口报"目录不存在" | 服务器上 `LOCAL_MATERIAL_DIR` 未指向真实目录，检查 systemd 服务里的 Environment 与目录权限 |
| 页面报错 `launchAdvertiser 空引用` | 旧版本残留问题，当前代码已清理，请确认上传的是最新代码 |
| 千川接口 40002（无权限） | 服务器上 token 过期或未迁移 token_store.db；重新在页面「设置」里确认账户 / 重新授权 |
| 页面打开慢 | 首次加载报表/商品会拉千川接口（已做 TTL 缓存，10–40 秒属正常）；Nginx `proxy_read_timeout` 已放宽到 300s |
| 上传大视频失败 | Nginx `client_max_body_size` 已设 200m；若还小可自行调大 |
| 数据库锁（database is locked） | 确认 uvicorn 是**单进程**（systemd 模板已保证），不要手动加 --workers |
